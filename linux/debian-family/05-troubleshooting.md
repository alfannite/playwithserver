## Symptom to Fix Matrix

| Symptom | First Diagnostic Command | Common Root Cause | Targeted Fix |
| :--- | :--- | :--- | :--- |
| `Could not get lock /var/lib/dpkg/lock-frontend` | `lsof /var/lib/dpkg/lock-frontend` | `unattended-upgrades` or another `apt` process running | Wait for PID to finish; never delete lock while PID is alive |
| `dpkg was interrupted` | `dpkg --audit` | SSH dropped or power lost mid-upgrade | Run `dpkg --configure -a && apt-get install -f` |
| `The following packages have been kept back` | `apt-cache policy <pkg>` | Phased Ubuntu update or new dependency required | Run `apt-get full-upgrade` or inspect phased rollout |
| Proxmox `apt update` returns `401 Unauthorized` | `grep -rn enterprise /etc/apt/` | `pve-enterprise.list` enabled without subscription | Comment out enterprise repos; add `pve-no-subscription` |
| Service fails with `Permission denied` despite `chmod` | `dmesg -T \| grep -i apparmor` | AppArmor profile blocking non-default path | Add path to `/etc/apparmor.d/local/<profile>` and reload |
| Docker container port reachable despite `ufw deny` | `iptables -L DOCKER-USER -n -v` | Docker DNAT bypasses `ufw` `INPUT` chain | Bind to `127.0.0.1` or filter on `DOCKER-USER` |
| `/boot` full during kernel upgrade | `df -h /boot; dpkg -l 'linux-image-*'` | Accumulated old kernels | `apt-get autoremove --purge` (keep current + 1 previous) |
| Proxmox `/etc/pve` mounted read-only | `pvecm status` | Cluster lost quorum (`Expected votes` not met) | Restore offline nodes or fix Corosync network |

## APT and DPKG Recovery

### Diagnose Held Locks Safely

`[ROOT]`
```bash
# Identify which process holds APT/DPKG locks
fuser -v /var/lib/dpkg/lock-frontend /var/lib/apt/lists/lock /var/cache/apt/archives/lock
ps -fp "$(fuser /var/lib/dpkg/lock-frontend 2>/dev/null)"
```

> **Watch out:** Never blindly run `rm -f /var/lib/dpkg/lock*` while `unattended-upgrade` or `apt-get` is actively unpacking packages; running a second `dpkg` concurrently corrupts `/var/lib/dpkg/status`. Only remove stale locks after confirming zero `apt`/`dpkg` processes exist.

### Repair Interrupted or Broken Dependencies

`[ROOT]`
```bash
dpkg --audit
dpkg --configure -a
apt-get install -f
apt-get check
```

### Clear Full `/boot` Partition Safely

Check your currently running kernel before removing anything:

`[ROOT]`
```bash
uname -r
dpkg --list 'linux-image-*' | awk '/^ii/ {print $2}'

# Remove orphaned kernels safely via APT
apt-get autoremove --purge -y
```

If `apt-get` refuses to run because `/boot` has 0 bytes free to build an initramfs, remove one specific **non-running** old kernel package directly via `dpkg --purge linux-image-<old-version>`, then run `apt-get -f install` and `update-grub`.

## Netplan, DNS, and Bridge Debugging

### Ubuntu Netplan Validation

`[ROOT]`
```bash
# Generate and inspect systemd-networkd units without applying
netplan generate --debug
networkctl status
networkctl list

# Check resolved DNS configuration per link
resolvectl status
```

### Debian and Proxmox Bridge Inspection

`[ROOT]`
```bash
# Inspect bridge member ports and VLAN filter table
bridge link show
bridge vlan show

# Validate /etc/network/interfaces syntax on ifupdown2 hosts
ifreload -a -n -v
```

> **Watch out:** On Ubuntu 22.04/24.04 cloud images, `systemd-networkd-wait-online.service` can stall boot for 2 minutes if a configured secondary NIC is unplugged. Mark non-critical links with `optional: true` in `/etc/netplan/*.yaml`.

## UFW and AppArmor Denial Triage

### Trace UFW Drops Live

Enable medium-level logging briefly and watch dropped packets in kernel logs:

`[ROOT]`
```bash
ufw logging low
journalctl -k -f --grep='\[UFW BLOCK\]'
```

Inspect the actual underlying `nftables` or `iptables` rules generated by `ufw`:

`[ROOT]`
```bash
ufw show raw | head -n 60
```

### Isolate AppArmor Denials

`[ROOT]`
```bash
# List recent AppArmor denials with profile name, operation, and target path
journalctl -k --grep='apparmor="DENIED"' --since "1 hour ago" --no-pager

# Temporarily switch one profile to complain mode to confirm it is the root cause
aa-complain /usr/sbin/nginx
systemctl restart nginx
```

Once verified, generate the exact minimal local override with `aa-logprof` and immediately restore enforcement (`aa-enforce /usr/sbin/nginx`).

## Proxmox VE Specific Diagnostics

### Cluster Quorum and `pmxcfs` Triage

`[ROOT]`
```bash
# Check cluster membership, ring status, and vote count
pvecm status
corosync-cfgtool -s

# Check core Proxmox daemon health
systemctl status pve-cluster pvedaemon pveproxy pvestatd --no-pager

# Inspect recent VM/backup task logs directly from CLI
ls -lt /var/log/pve/tasks/active
```

### Stuck VM or Locked Backup State

If a VM backup or snapshot crashes and leaves a VM locked (`VM is locked (backup)`):

`[ROOT]`
```bash
# Verify no active vzdump/backup process is still writing to the VM
ps aux | grep -E 'vzdump|kvm.*-id 105'

# Unlock VMID 105 only after confirming the task is truly dead
qm unlock 105
qm status 105 --verbose
```

## High-Signal One-Liners

```bash
# Show recent APT installs, upgrades, and removals with timestamps [NON-ROOT]
zgrep -hE '^(Start-Date|Commandline|Upgrade|Install|Remove|Purge):' /var/log/apt/history.log* | tail -n 40

# Find which packages are held back by Ubuntu phased updates [NON-ROOT]
apt-cache policy $(apt-get -s upgrade | awk '/^  / {print $1}') | grep -E '^[^ ]|phased'

# Check services still referencing deleted shared libraries after patching [ROOT]
needrestart -b

# Test DNS resolution bypassing systemd-resolved stub (127.0.0.53) [NON-ROOT]
resolvectl dns; dig +short @1.1.1.1 deb.debian.org

# List all listening Proxmox/Debian sockets with owning unit names [ROOT]
ss -tulnp
```
